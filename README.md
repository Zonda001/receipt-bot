# receipt-bot

Telegram-бот для командного обліку чеків: фото -> розпізнана сума -> підтвердження -> Google Drive + Google Sheets.

> Чернетка. Повний README (запуск, авторизація, архітектура, тестування) — в кінці роботи.

## Запуск (локально)

```bash
python -m venv .venv
.venv/bin/pip install -r requirements.txt
cp .env.example .env   # заповнити значення
python -m receipt_bot
```

## Розпізнавання: замір 25.09

24 справжні документи (фото з Telegram, 960×1280): 2 чеки супермаркету, 14 квитанцій ПриватБанку, аптека,
довгий і зім'яті чеки, рахунок, обмін валют, чек боком.

| Варіант | Правильна сума |
|---|---|
| Старий промпт ("shop receipts"), `is_receipt` першим у схемі — Groq Qwen | 2/24 (19 разів "не чек") |
| Новий промпт (будь-які документи про оплату), суми перед вердиктом — Groq Qwen | 11/11 (далі денний ліміт) |
| Те саме — Cloudflare Gemma 4 | **22/24**, обидві помилки — хибна цифра (591.20 замість 591.26) |

Звідси: Cloudflare основний (~1100 чеків/добу безкоштовно, ~9 нейронів на чек), Groq запасний (~80/добу).
Хибну цифру ловить лише людина, тому бот ніколи не записує суму без підтвердження.

## Відомі обмеження

- **Вхід через код (device flow):** якщо людина введе код, який їй хтось переслав, бот прив'яже чужий Telegram до її
  акаунта. Що це обмежує: один email — один Telegram (попередній акаунт відключається й отримує попередження),
  у кожному рядку таблиці — Telegram ID відправника, не більше 100 записів на людину за добу.
- **Доступ** — лише права редагування, видані конкретній людині. Не рахуються Google-групи, доступ на весь домен
  (особистий акаунт може мати корпоративну адресу) і «будь-хто з посиланням» (бот публічний).
- **Якщо Google не відповів вчасно**, бот шукає рядок за ID чека; якщо й цього не вийшло — просить перевірити таблицю
  перед повтором, а фото не видаляє.
- Бот працює лише в особистих чатах. Процес бота запускається від користувача `ubuntu`, але під жорсткими
  обмеженнями systemd (див. `deploy/receipt-bot.service`); окремий системний користувач — наступний крок.
